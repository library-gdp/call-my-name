# 채용공고 원문 추출 계약

## 선택 기준

출처에서 확인되는 다음 내용을 공고에 직접 관련된 정보로 보고 포함하라.

- 모집공고명과 기업명
- 접수 시작일과 접수 마감일
- 모집분야와 직무명
- Job Description, 주요 업무, 역할과 책임
- 응시자격, 필수요건과 지원자격
- 우대조건
- 근무지
- 신입·경력 구분, 경력무관 여부와 요구 경력
- 전형절차, 각 전형의 일정과 발표일

다음처럼 공고와 간접적으로 관련되어 지원 판단에 도움이 되는 정보도 포함하라.

- 복리후생
- 연봉, 보상과 수당
- 고용형태, 근무시간, 계약기간과 근무방식 등 근무조건

위 목록에 없더라도 특정 공고의 직무, 지원, 근무 또는 전형과 관련됐을 가능성이 있으면 포함하라. 관련성을 확정할 수 없다는 이유만으로 버리지 마라.

다음 내용은 제외하라.

- HTML 태그, CSS, JavaScript, JSON 상태값과 추적 코드
- 전역 header·footer·navigation, cookie 안내, 로그인 UI와 사이트 공통 템플릿
- 환영인사와 직무 정보가 없는 일반 홍보 문구
- 여러 공고에 반복되는 개인정보처리방침, 고용평등·법규 준수, 신고·문의와 편의 제공 안내 등 법적 footer. 단, 해당 공고의 지원자격·우대조건·근무조건을 직접 바꾸는 내용은 포함한다.
- 조회수, 즐겨찾기, 공유, 홈페이지 방문, 앱 설치와 유사 공고 추천
- 다른 모집공고의 제목이나 링크

## 원문 보존

- 출처의 문장과 항목명을 그대로 옮겨라. 축약, 바꿔쓰기, 문체 통일, 맞춤법 교정 또는 번역을 하지 마라.
- 제목, 단락, 목록, 표의 행·열 관계와 본문 순서를 가능한 한 유지하라.
- 웹 표현을 Markdown으로 바꾸는 과정에서만 최소한의 구조 변환을 허용한다. 장식용 아이콘의 대체 텍스트처럼 의미 없는 표현은 버려라.
- 반복이 사이트 UI 때문에 생긴 것이 확실할 때만 중복을 제거하라. 공고 본문에서 의도적으로 반복한 내용은 보존하라.
- 출처에 없는 필드나 값을 추론하지 마라. `정보 없음`, `미정` 같은 문구도 출처에 실제로 있을 때만 기록하라.
- 이미지형 공고는 보이는 문구를 원문대로 판독하고, 읽을 수 없는 글자를 추측하지 마라. 표나 배치가 의미를 가지면 그 관계를 Markdown으로 보존하라.

## 파일명

수집을 실행한 지역 날짜를 `YYYY_MM_DD`로 표현하고 다음 형식을 사용하라.

```text
<SHORT_POSTING_TITLE>_<YYYY_MM_DD>.md
```

- `SHORT_POSTING_TITLE`은 원문의 모집공고명을 의미가 유지되는 범위에서 짧게 줄여 만들라.
- 공백과 구분 문자는 `_`로 바꾸고 연속된 `_`는 하나로 합쳐라.
- 영문은 대문자로 바꾸고, 한글과 숫자는 보존하라. 경로 구분자, 제어 문자와 파일명에 안전하지 않은 문자는 제거하라.
- 같은 날짜에 파일명이 충돌하면 공고명 뒤에 기업명을 같은 규칙으로 붙여 구분하라. 그래도 충돌하면 마지막에 `_2`, `_3`처럼 번호를 붙여라.
- 동일한 URL과 공고를 같은 날 다시 수집하면 새 번호 파일을 만들지 말고 기존 대상 파일을 원자적으로 교체하라.

## 파일 본문

각 파일은 아래 최소 메타데이터 다음에 정제한 공고 원문을 이어서 기록하라.

```markdown
# <출처의 모집공고명>

- 기업명: <출처에 표시된 기업명>
- 원문 URL: <입력 URL 또는 확인한 공식 대체 원문 URL>
- 수집일: YYYY-MM-DD

<공고 원문의 제목·단락·목록·표를 출처 순서대로 기록>
```

- `수집일`은 파일명의 날짜와 같아야 한다.
- 기업명은 공고나 공고를 게시한 공식 채용 페이지에 표시된 정확한 이름을 사용하라. 확인할 수 없으면 추측하지 말고 해당 줄을 생략하라.
- redirect가 발생해도 사용자가 제공한 URL을 원문 URL로 유지한다. 공개 대체 원문을 사용한 경우에만 실제 대체 URL을 기록하고 완료 보고에 원 URL과의 관계를 밝혀라.
- 원문에 있던 제목을 메타데이터 제목 다음에 중복해서 쓰지 마라.
- 원문에 없는 표준 필드 제목을 새로 만들거나 필드별 요약표를 추가하지 마라.
- 접근 오류, CAPTCHA, 로그인 필요, 빈 본문과 판독 불가 같은 진단은 공고 파일에 넣지 마라.

## 실패와 부분 성공

- 공고명과 모집 관련 본문을 신뢰할 수 있게 확인하지 못하면 해당 URL의 파일을 만들지 마라.
- `JavaScript를 활성화하라`는 안내나 빈 app shell은 그 자체로 접근 차단이 아니다. 브라우저 렌더링, 공개 구조화 데이터와 페이지가 직접 사용하는 인증 없는 데이터 요청까지 확인한 뒤 본문을 얻지 못한 경우에만 실패 처리하라.
- 일부 선택 항목이 원문에 없다는 이유로 실패 처리하지 마라. 확인되는 공고 본문만 보존하라.
- 여러 URL 중 하나가 실패해도 성공한 URL의 파일은 저장하라.
- 완료 보고에서 실패 URL과 `접근 차단`, `로그인 필요`, `본문 없음`, `이미지 판독 불가`처럼 확인한 이유를 구분하라.
